MikroTik hEX refresh (E50UG) + TP-Link Omada TL-SG3428MP (Standalone Web GUI)

ฉบับใช้งานจริงบนโต๊ะแข่ง (ปรับปรุงแทนสวิตช์ Cisco เดิมที่ค้าง) — ขั้นตอนเรียงลำดับจับมือทำทีละคลิก อ้างอิงเมนูจริงของสวิตช์ TP-Link JetStream / Omada TL-SG3428MP ในโหมด Standalone และ RouterOS v7 บน MikroTik E50UG ครบเกณฑ์คะแนน 10 คะแนนเต็ม

📌 5 กฎเหล็กที่ต้องรู้เมื่อเปลี่ยนจาก Cisco CBS350 มาเป็น TP-Link TL-SG3428MP:
  1. ไอพีโรงงานของ TP-Link คือ 192.168.0.1/24 (ผู้ใช้ admin / รหัส admin) คนละวงกับ MikroTik (192.168.1.1/24) จึงไม่ชนกัน
  2. การตั้งพอร์ต Access บน TP-Link ต้องทำ 2 หน้าเสมอ:
    • หน้าที่ 1 (แท็บ VLAN Config): เอาพอร์ตเข้า VLAN แบบ Untagged
    • หน้าที่ 2 (แท็บ Port Config): เปลี่ยนค่า PVID ของพอร์ตนั้นให้ตรงกับเลข VLAN (ถ้าลืมเปลี่ยน PVID เครื่องลูกจะไม่ได้รับ IP และวิ่งเข้า VLAN 1 เหมือนเดิม!)
  3. การจำกัดช่วง DHCP .100 – .199 บน TP-Link: ใช้เมนู DHCP Server → Excluded Address กันช่วง .1–.99 และ .200–.254 ออก
  4. ไม่ต้องยุ่งกับเมนู DHCP Relay และ DHCP L2 Relay เด็ดขาด: เพราะตัวสวิตช์ TP-Link เป็น DHCP Server เองอยู่แล้ว ให้ปล่อย Relay เป็น Disable ทั้งหมด
  5. ต้องกดปุ่ม Save (มุมขวาบนสุด) ทุกครั้ง: การกด Create หรือ Apply แค่เก็บลง RAM ชั่วคราว ถ้าไม่กด Save พอไฟดับค่าจะหายทั้งหมด!

1. ใครทำอะไร และคะแนนมาจากไหน (10 คะแนนเต็ม)

ในโครงสร้างนี้ สวิตช์ TP-Link TL-SG3428MP ทำงานชั้น 3 (Layer 3) ทั้งหมด ส่วน MikroTik ทำเฉพาะขอบนอก (WAN + NAT + Route ขากลับ)

งานในเกณฑ์คะแนน (10 คะแนน) ทำที่เครื่อง จุดที่ตั้งค่าจริง
VLAN วงเซิร์ฟเวอร์กับวง dev ที่ไม่ใช่ VLAN เริ่มต้น (2 คะแนน) TP-Link SG3428MP เมนู L2 FEATURES → VLAN → 802.1Q VLAN สร้าง VLAN 10, 20, 99 เลือกพอร์ตแบบ Untagged และตั้ง PVID ให้ตรงกัน
Inter-VLAN Routing (3 คะแนน) TP-Link SG3428MP เมนู L3 FEATURES → Interface สร้าง SVI 192.168.10.1/24 และ 192.168.20.1/24 (สวิตช์เปิด IPv4 Routing ข้ามวงให้อัตโนมัติ)
DHCP ทั้งสองวง + DHCP Snooping (3 คะแนน) TP-Link SG3428MP เมนู L3 FEATURES → DHCP Service → DHCP Server สร้าง 2 พูล + ตั้ง Excluded Address และเปิด SECURITY → IP-MAC Binding → DHCP Snooping บน VLAN 10, 20
NAT ทั้งสองวงออกอินเทอร์เน็ต (2 คะแนน) MikroTik E50UG ทำ masquerade ขาออก ether1 และใส่ Static Route ขากลับไปหา 192.168.10.0/24 และ 192.168.20.0/24 ผ่าน 192.168.99.2

การไหลของแพ็กเก็ตที่ต้องต่อกันได้จริง:

  1. โน้ตบุ๊คใน VLAN 20 ใช้เกตเวย์ 192.168.20.1 (SVI ของสวิตช์ TP-Link) ไม่ใช่ไอพีของ MikroTik
  2. เวลาคุยข้ามไปเครื่องใน VLAN 10 (เช่น Proxmox 192.168.10.10) สวิตช์ TP-Link ส่งข้ามวงให้เองโดยตรง แพ็กเก็ตไม่ผ่าน MikroTik
  3. เวลาออกอินเทอร์เน็ต สวิตช์ TP-Link ส่งตาม Default Route (0.0.0.0/0) ไปที่ 192.168.99.1 (ether3) แล้ว MikroTik ทำ NAT ออก ether1
  4. ขากลับ MikroTik มี Route 192.168.10.0/24 และ 192.168.20.0/24 ชี้กลับมาที่ 192.168.99.2 (ขา VLAN 99 ของสวิตช์ TP-Link)

3. ลำดับการต่อสาย — อย่าต่อสายครบทุกเส้นตั้งแต่ต้น!

ขั้นที่ ต่อสายอะไร ยังไม่ต่ออะไร เหตุผลที่ขั้นนี้ต้องมาก่อน
1 โน้ตบุ๊คกับ ether2 (MikroTik) และโน้ตบุ๊คกับ พอร์ต 24 ของสวิตช์ TP-Link (ทำทีละเครื่องหรือคนละเครื่องได้) ยังไม่ต่อ ether3 ↔ Port 1 และยังไม่ต่อ ether1 ไปกรรมการ ตั้งค่าไอพีลิงก์และตาราง Route ให้ครบก่อน สายขึ้นแล้วจะได้ไม่สับสน
2 ตั้งค่า MikroTik (บทที่ 4) กับ TP-Link (บทที่ 5) ให้ครบทุกหัวข้อ แล้วกด Save บนสวิตช์ ยังไม่ต่อสายลิงก์ ให้ SVI, DHCP และ Route ทั้งสองฝั่งพร้อมก่อนแพ็กเก็ตเริ่มวิ่ง
3 ต่อสาย LAN ระหว่าง ether3 กับ Port 1 แล้วทดสอบ Ping และรับ DHCP (บทที่ 6) ยังไม่ต่อเครื่องลูกจำนวนมาก / WAN ถ้าลิงก์ชั้น 3 ไม่ติด จะได้รู้ทันทีไม่ต้องไปโทษ DHCP หรือ NAT
4 วันแข่งได้ไอพี WAN ค่อยต่อ ether1 ใส่ไอพีกับ Default Route แล้วทดสอบ NAT (บทที่ 7) — WAN เปลี่ยนตามโต๊ะแข่ง ใช้ masquerade จะไม่ผูกกับไอพีตายตัว

4. ตั้งค่า MikroTik E50UG (ด้วยโปรแกรม Winbox)

ทำบนเครื่องที่ยังไม่ต่อสาย ether3 เข้าสวิตช์ ต่อโน้ตบุ๊คที่ ether2 (หรือเข้าผ่าน MAC Address ในแท็บ Neighbors)

4.1 รีเซ็ตเป็นเครื่องเปล่า (No Default Configuration)

  1. เปิด Winbox ไปที่แท็บ Neighbors คลิกที่เลข MAC Address ของ MikroTik
  2. เข้าด้วยผู้ใช้ admin รหัสว่าง (ถ้าระบบบังคับตั้งรหัสใหม่ให้ตั้งแล้วจดไว้)
  3. ไปที่เมนูซ้าย System → Reset Configuration
  4. ติ๊กถูกที่ช่อง [✓] No Default Configuration และ [✓] Do Not Backup
  5. กดปุ่ม Reset Configuration ยืนยัน เครื่องจะรีบูตแล้วเข้าใหม่ผ่าน MAC Address อีกครั้ง

คำสั่งเทียบเท่าใน New Terminal:

/system reset-configuration no-defaults=yes skip-backup=yes
⚠️ ห้ามใช้เมนู Quick Set หลังรีเซ็ตเด็ดขาด! เพราะจะแอบสร้าง Bridge และ DHCP ของตัวเองกลับมาทับพอร์ต ether3

4.2 ใส่ไอพีจัดการ (ether2) และไอพีลิงก์ไปสวิตช์ (ether3)

ไปที่เมนูซ้าย IP → Addresses กดปุ่ม + สองครั้งเพื่อเพิ่ม 2 แถวนี้:

แถวที่ ช่อง Address ช่อง Interface คำอธิบาย
แถวที่ 1 192.168.1.1/24 ether2 พอร์ตจัดการเราเตอร์ (กด OK)
แถวที่ 2 192.168.99.1/30 ether3 ลิงก์เชื่อมไปพอร์ต 1 ของสวิตช์ TP-Link (กด OK)

4.3 ใส่ Static Route ขากลับไปหาวงเซิร์ฟเวอร์ (VLAN 10) และวง dev (VLAN 20)

ไปที่เมนูซ้าย IP → Routes กดปุ่ม + สองครั้ง:

ชื่อช่องใน Winbox ค่าแถวที่ 1 (กลับไปวง Server) ค่าแถวที่ 2 (กลับไปวง Dev)
Dst. Address 192.168.10.0/24 192.168.20.0/24
Gateway 192.168.99.2 192.168.99.2

กด OK ทั้งคู่ (ตอนนี้ยังไม่ได้เสียบสายลิงก์ แถวจะขึ้นสถานะ unreachable เป็นเรื่องปกติ พอเสียบสายในบทที่ 6 จะเปลี่ยนเป็น reachable ทันที)

4.4 ใส่กฎ NAT แบบ Masquerade

ไปที่เมนูซ้าย IP → Firewall เลือกแท็บ NAT แล้วกดปุ่ม +:

ชื่อช่อง (แท็บ) ค่าที่ใส่
Chain (แท็บ General) srcnat
Out. Interface (แท็บ General) ether1 (ระวัง! ต้องใส่ช่อง Out. Interface เท่านั้น ห้ามใส่ In. Interface)
Action (แท็บ Action) masquerade

กด OK

4.5 ใส่ไอพีขา WAN (ether1) และ Default Route ออกอินเทอร์เน็ต (ห้ามลืมเด็ดขาด!)

🚨 จุดที่คนลืมบ่อยที่สุดตอนซ้อมและวันแข่ง: ถ้าตั้งค่าแค่ ether2, ether3 และ NAT แต่ลืมใส่ ไอพีขา WAN บน ether1 และลืมใส่ Default Route (0.0.0.0/0) ชี้ไปเกตเวย์ WAN เครื่องลูกจะปิง 192.168.99.1 ติด แต่จะออกอินเทอร์เน็ต (8.8.8.8 / google.com) ไม่ได้เลย!

ให้ใส่ค่า WAN บน MikroTik ทันที (ถ้าซ้อมในห้องแล็บใช้ค่าห้องแล็บ เช่น 172.16.48.29/22 เกตเวย์ 172.16.48.1 หรือวันแข่งใช้ค่าตามกระดาษที่กรรมการแจก):

ขั้นตอนที่ต้องทำบน MikroTik เมนูใน Winbox ค่าที่ต้องใส่
1. ใส่ IP ขา WAN บน ether1
(กรณี Static IP)		 IP → Addresses กดปุ่ม + • Address: ไอพี WAN พร้อมมาสก์ (เช่น 172.16.48.29/22)
• Interface: เลือก ether1 แล้วกด OK
2. ใส่ Default Route ออกเน็ต
(กรณี Static IP)		 IP → Routes กดปุ่ม + • Dst. Address: 0.0.0.0/0
• Gateway: ไอพีเกตเวย์ของ WAN (เช่น 172.16.48.1) แล้วกด OK
(ห้ามใส่ไอพีสวิตช์ตัวเองในช่องนี้เด็ดขาด)
(ทางเลือก) กรณีเน็ตห้องซ้อมหรือกรรมการแจกเป็น DHCP IP → DHCP Client กดปุ่ม + • Interface: เลือก ether1
• ติ๊ก Use Peer DNS และ Add Default Route: yes แล้วกด OK (จะได้ทั้ง IP และ Route 0.0.0.0/0 อัตโนมัติ)

4.6 ตั้งค่า DNS Server บน MikroTik (เพื่อให้เปิดเว็บชื่อโดเมนเช่น google.com ได้)

ไปที่เมนูซ้าย IP → DNS แล้วกรอกค่าตามตารางนี้:

ชื่อช่องในหน้า DNS Settings ค่าที่ต้องใส่
Servers พิมพ์ 1.1.1.1 (กดลูกศรลงเพิ่มช่องที่สอง ใส่ 8.8.8.8)
Allow Remote Requests ติ๊กเครื่องหมายถูก [✓] Allow Remote Requests (เพื่อให้เครื่องลูกและสวิตช์ถาม DNS ผ่าน MikroTik ได้ด้วย)

กดปุ่ม OK (คำสั่งใน New Terminal คือ /ip dns set servers=1.1.1.1,8.8.8.8 allow-remote-requests=yes)

ชุดคำสั่งรวบยอดฝั่ง MikroTik (วางใน New Terminal หลังรีเซ็ตแบบ no-defaults)

# 1. ใส่ไอพีจัดการ (ether2), ไอพีลิงก์สวิตช์ (ether3), และไอพีขา WAN (ether1)
/ip address
add address=192.168.1.1/24 interface=ether2 comment="MGMT"
add address=192.168.99.1/30 interface=ether3 comment="LINK_TO_SWITCH"
add address=172.16.48.29/22 interface=ether1 comment="WAN_IP_CHANGE_ON_MATCH_DAY"

# 2. ใส่ Route ขากลับเข้า VLAN 10, 20 และใส่ Default Route ออกอินเทอร์เน็ต (0.0.0.0/0)
/ip route
add dst-address=192.168.10.0/24 gateway=192.168.99.2 comment="RETURN_VLAN10"
add dst-address=192.168.20.0/24 gateway=192.168.99.2 comment="RETURN_VLAN20"
add dst-address=0.0.0.0/0 gateway=172.16.48.1 comment="WAN_GATEWAY"

# 3. ตั้งค่า DNS และ NAT Masquerade ขาออก ether1
/ip dns set servers=1.1.1.1,8.8.8.8 allow-remote-requests=yes
/ip firewall nat
add chain=srcnat out-interface=ether1 action=masquerade comment="WAN_NAT"
✅ เช็คลิสต์ตรวจทาน MikroTik ก่อนจบหัวข้อที่ 4 (ต้องครบทั้ง 4 ข้อ!):
  • หน้า IP → Addresses ต้องมีครบ 3 แถว คือ ether1 (WAN), ether2 (.1.1/24), และ ether3 (.99.1/30)
  • หน้า IP → Routes ต้องมีครบ 3 เส้นทาง คือ 0.0.0.0/0 (ชี้ไปเกตเวย์ WAN), 192.168.10.0/24 (ชี้ไป 192.168.99.2), และ 192.168.20.0/24 (ชี้ไป 192.168.99.2)
  • หน้า IP → DNS ต้องมี Servers 1.1.1.1, 8.8.8.8 และติ๊กถูก [✓] Allow Remote Requests
  • หน้า IP → Firewall → NAT ต้องมี srcnat ออก ether1 แบบ masquerade

5. ตั้งค่าสวิตช์ TP-Link Omada TL-SG3428MP (เว็บ GUI แบบจับมือทำ)

ทำบนเครื่องสวิตช์ที่ยังไม่ต่อพอร์ต 1 เข้ากับ MikroTik ให้เสียบสาย LAN จากโน้ตบุ๊คเข้าที่ พอร์ต 24 ของสวิตช์

5.1 รีเซ็ตและเข้าเครื่องสวิตช์ครั้งแรก

  1. กรณีเครื่องเคยถูกตั้งค่าไว้แล้ว (วิธีรีเซ็ตค่าโรงงาน): ใช้คลิปหนีบกระดาษกดปุ่ม Reset ด้านหน้าสวิตช์ค้างไว้ 5–10 วินาที จนไฟ LED ทุกดวงกระพริบพร้อมกันแล้วปล่อย รอเครื่องบูตใหม่ 1–2 นาที
  2. ตั้งไอพีโน้ตบุ๊คเป็นค่าตายตัว: IP Address 192.168.0.10 มาสก์ 255.255.255.0 (เกตเวย์เว้นว่างไว้)
  3. เสียบสาย LAN จากโน้ตบุ๊คเข้าที่ พอร์ต 24 ของสวิตช์ TP-Link
  4. เปิดเบราว์เซอร์ไปที่ http://192.168.0.1
  5. หน้าล็อกอินใส่ Username: admin และ Password: admin แล้วกด Login
  6. ตั้งรหัสผ่านใหม่: ครั้งแรกสวิตช์จะบังคับเปลี่ยนรหัสผ่าน ให้ตั้งรหัสที่มีตัวพิมพ์ใหญ่ พิมพ์เล็ก ตัวเลข (เช่น Skill69@admin) แล้วจดไว้ให้ทั้งทีมทราบ
  7. ล็อกไอพี VLAN 1 ให้เป็น Static: ไปที่เมนูด้านบนสุด L3 FEATURES → เมนูซ้าย Interface → กดปุ่ม Edit (รูปดินสอ) ที่แถว VLAN 1 → ตรวจว่า IPv4 Address Mode เป็น Static (192.168.0.1 / 255.255.255.0) แล้วกด Apply

5.6 เปิด DHCP Snooping บน VLAN 10 และ VLAN 20

  1. คลิกแถบเมนูด้านบนสุด SECURITY → เมนูซ้ายคลิก IP-MAC Binding → คลิก DHCP Snooping (หรือในบางเฟิร์มแวร์ใช้ชื่อ Network Security → DHCP Snooping)
  2. ในแท็บ Global Config ตั้งค่าดังนี้:
    • DHCP Snooping: ติ๊กเลือก [✓] Enable
    • Global Snooping VLANs (หรือ VLAN Config): ติ๊กเปิดเฉพาะ VLAN 10 และ VLAN 20 (ไม่ต้องเปิดบน VLAN 1 และ 99)
    • Option 82: ปล่อยเป็น Disable (ไม่เปิด)
  3. กดปุ่ม Apply
  4. ในแท็บ Port Config: ปล่อยพอร์ตลูกข่ายเป็นค่าเริ่มต้นได้เลย และ ห้ามไปเปิด ARP Inspection หรือ IP Source Guard เพราะจะทำให้เครื่องเซิร์ฟเวอร์ที่ตั้ง Static IP ออกเน็ตไม่ได้

5.7 กด Save และสำรองไฟล์คอนฟิกเก็บไว้ในโน้ตบุ๊ค

  1. คลิกปุ่ม Save (รูปดิสก์มุมขวาบนสุดของหน้าเว็บ) แล้วกดยืนยัน
  2. ไปที่เมนูด้านบนสุด SYSTEM → เมนูซ้าย System Tools → Backup & Restore (หรือ Config Backup) → กดปุ่ม Backup Config เพื่อดาวน์โหลดไฟล์ .cfg เก็บไว้ในโน้ตบุ๊คของทีม

6. ต่อสายลิงก์ แล้วทดสอบทีละขั้น

ต่อสาย LAN เชื่อมระหว่าง MikroTik พอร์ต ether3 กับ TP-Link พอร์ต 1 (1/0/1) เท่านั้น (ห้ามต่อ ether2 เข้าสวิตช์) แล้วไล่ทดสอบตามลำดับนี้:

6.1 ทดสอบลิงก์ชั้น 3 ระหว่าง MikroTik กับ TP-Link

  • จาก Winbox เมนู Tools → Ping พิมพ์ 192.168.99.2 ต้องตอบกลับ
  • ดูที่เมนู IP → Routes ของ MikroTik แถว 192.168.10.0/24 และ 192.168.20.0/24 ต้องเปลี่ยนสถานะเป็น reachable
  • ถ้าไม่ติด: เช็คไฟพอร์ต 1, เช็คว่าพอร์ต 1 อยู่ VLAN 99 Untagged + PVID = 99, และเช็คมาสก์ /30 (255.255.255.252) ทั้งสองฝั่ง

6.2 ทดสอบ DHCP และเกตเวย์วง dev (พอร์ต 9–16)

  1. ย้ายสาย LAN ของโน้ตบุ๊คมาเสียบที่ พอร์ต 9 ของสวิตช์ TP-Link แล้วตั้งการ์ดแลนโน้ตบุ๊คเป็นรับ DHCP (Obtain an IP address automatically)
  2. เปิด Command Prompt พิมพ์ ipconfig /all ต้องได้รับไอพีในช่วง 192.168.20.100 – 199 มาสก์ 255.255.255.0 เกตเวย์ 192.168.20.1 และ DNS 1.1.1.1
  3. สั่งทดสอบ Ping จากโน้ตบุ๊คตามลำดับ:
    • ping 192.168.20.1 → ต้องติด (เกตเวย์วงตัวเอง)
    • ping 192.168.10.1 → ต้องติด (Inter-VLAN บนสวิตช์ TP-Link)
    • ping 192.168.99.1 → ต้องติด (สวิตช์ส่งต่อไปถึง MikroTik ตาม Default Route)

6.3 ทดสอบ Inter-VLAN ไปยังเครื่องเซิร์ฟเวอร์ Proxmox (พอร์ต 2–8)

  • ต่อสาย LAN จากเครื่อง Proxmox (ตั้งไอพี 192.168.10.10/24 เกตเวย์ 192.168.10.1 ไม่ใส่ VLAN tag) เข้าที่ พอร์ต 2 ของสวิตช์ TP-Link
  • จากโน้ตบุ๊ควง 20 (พอร์ต 9) สั่ง ping 192.168.10.10 ต้องติด และเปิดเว็บเข้า https://192.168.10.10:8006 ได้ทันที

เขียนค่าที่กรรมการแจกลงในตารางนี้ก่อนกรอกลงเครื่อง MikroTik (ฝั่งสวิตช์ TP-Link ไม่ต้องแก้อะไรอีก):

  1. ping 192.168.99.1 (ยังต้องติด)
  2. ping <ไอพีเกตเวย์ WAN ของกรรมการ> (ควรติด)
  3. ping 8.8.8.8 (ควรติด)
  4. เปิดเว็บ เช่น https://1.1.1.1 หรือ ping google.com (ควรออกเน็ตได้ครบทั้งสองวง)

8. แผ่นเทียบเกณฑ์คะแนน (ใช้ตรวจเช็คก่อนยกมือเรียกกรรมการ)

ข้อเกณฑ์คะแนน คะแนน สิ่งที่กรรมการต้องเห็น วิธีทดสอบเร็ว
VLAN เซิร์ฟเวอร์กับ dev ไม่ใช่ค่าเริ่มต้น 2 หน้า 802.1Q VLAN มี VLAN 10 (พอร์ต 2–8, PVID 10) และ VLAN 20 (พอร์ต 9–16, PVID 20) แยกจาก VLAN 1 เครื่องสองวงได้รับไอพีคนละซับเน็ต (.10.x กับ .20.x)

9. เมื่อมีปัญหา — ตารางไล่แก้จากชั้นล่างขึ้นมา

อาการที่พบ สาเหตุที่พบบ่อยที่สุดบน TP-Link สิ่งที่ต้องตรวจและวิธีแก้
เสียบโน้ตบุ๊คพอร์ต 9 แล้วไม่ได้รับไอพี DHCP (ได้ 169.254.x.x) ลืมตั้งค่า PVID ในแท็บ Port Config (พอร์ตยังเป็น PVID 1) หรือลืมติ๊ก Enable DHCP Server ด้านบน ไปที่ L2 FEATURES → VLAN → 802.1Q VLAN → แท็บ Port Config ตั้ง PVID พอร์ต 9–16 เป็น 20 และพอร์ต 2–8 เป็น 10
ได้รับไอพี DHCP แต่ได้เลข .2 หรือ .3 (ไม่ใช่ .100) ลืมใส่ตาราง Excluded Address ในหน้า DHCP Server ไปที่แท็บ Excluded Address ใส่ช่วง .1–.99 และ .200–.254 ทั้งสองวง แล้วสั่ง ipconfig /renew ใหม่
ปิง 192.168.99.2 ไม่ติด พอร์ต 1 ยังไม่ได้ตั้ง Untagged VLAN 99 + PVID 99 หรือใส่มาสก์ผิด (ไม่ใช่ .252) เช็คพอร์ต 1 ใน 802.1Q VLAN (ทั้งแท็บ VLAN Config และ Port Config PVID=99) และเช็คมาสก์ /30 ทั้งสองเครื่อง
ปิงข้ามวง 10 ↔ 20 ได้ แต่ปิง 192.168.99.1 ไม่ติด ลืมใส่ Default Route บนสวิตช์ TP-Link หรือลืมใส่ Route ขากลับบน MikroTik เช็คหน้า Static Routing บน TP-Link (0.0.0.0/0 → 192.168.99.1) และเช็ค IP → Routes บน MikroTik ทั้งสองแถว
ตั้งค่าเสร็จแล้ว พอไฟดับ/รีบูต ค่าหายหมด กดแค่ปุ่ม Create / Apply แต่ลืมกดปุ่ม Save คลิกปุ่ม Save (รูปดิสก์มุมขวาบนสุดของเว็บ TP-Link) ทุกครั้งหลังจบแต่ละหัวข้อ
เปิดเข้าเว็บสวิตช์ 192.168.0.1 ไม่ได้ เสียบสายอยู่ในพอร์ต 1–16 ที่ย้ายไป VLAN 10/20/99 แล้ว หรือไอพีโน้ตบุ๊คไม่ใช่วง 0.x ย้ายสายไปเสียบ พอร์ต 24 ตั้งไอพีโน้ตบุ๊คเป็น 192.168.0.10/24 (หรือถ้าเสียบพอร์ต 9 ที่ได้ DHCP แล้ว ให้เข้าเว็บสวิตช์ผ่าน http://192.168.20.1 ได้เลย!)
