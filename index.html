ส่วนที่ 5 : GitLab Runner & SSH Deploy

ตั้งค่า GitLab Project + ติดตั้ง GitLab Runner + ทำ SSH Key ข้ามเครื่อง

หัวใจสำคัญของคะแนน CI/CD 4 Stages!

STEP 5.1: ดูรหัสผ่าน root ของ GitLab และสร้าง Project ชื่อ pes-app (หรือ task-app กรณีซ้อมส่วนที่ 6)

[VM1] 1. คำสั่งดูรหัสผ่านเริ่มต้นของบัญชี root บน GitLab 
sudo docker exec -it gitlab grep 'Password:' /etc/gitlab/initial_root_password
ขั้นตอนบนหน้าเว็บ GitLab (http://gitlab.mydomain.lab):
  1. ล็อกอินด้วย Username: root และ Password ที่ได้จากคำสั่งด้านบน
  2. คลิกปุ่ม Create a project $\rightarrow$ เลือก Create blank project
  3. ช่อง Project name พิมพ์: pes-app (แนะนำให้คนทำ Runner สร้างชื่อ pes-app ไว้เลย เพื่อที่คนทำโค้ดในส่วนที่ 7 จะได้สั่ง git push เข้ามาได้ทันทีไม่ต้องสร้างซ้ำ! ยกเว้นถ้าจะซ้อมเว็บจำลองส่วนที่ 6 ค่อยตั้งชื่อ task-app)
  4. ช่อง Visibility Level เลือกเป็น Public (เพื่อให้ดึงโค้ดและตรวจง่าย)
  5. สำคัญมาก: ติ๊กเครื่องหมายถูกออก จากช่อง "Initialize repository with a README" (เพื่อให้เป็น Repo เปล่า รอรับโค้ดจากเครื่อง PC) $\rightarrow$ กด Create project

STEP 5.2: สร้าง Project Runner บนหน้าเว็บ GitLab เพื่อเอา Token

  1. ในหน้าโปรเจกต์ pes-app (หรือ task-app) บนเว็บ GitLab ให้ไปที่เมนูซ้ายมือ: Settings $\rightarrow$ CI/CD
  2. มองหาหัวข้อ Runners แล้วกดปุ่ม Expand $\rightarrow$ คลิกปุ่ม New project runner (หรือ Create project runner)
  3. ในหน้าตั้งค่า Runner:
    • Operating systems: เลือก Linux
    • ในหัวข้อ Tags: ติ๊กถูกที่ช่อง [x] Run untagged jobs (สำคัญมาก! ถ้าไม่ติ๊ก Pipeline จะค้าง Pending ตลอดกาล)
    • เลื่อนลงล่างสุดแล้วกด Create runner
  4. ระบบจะแสดงค่า Runner authentication token (ขึ้นต้นด้วย glrt-...) ให้คัดลอกไว้ใช้ในขั้นตอนถัดไป ใช้ค่านี้เท่านั้น ไม่ใช้ Registration token แบบเก่าหรือ token ตัวอย่าง

⚠️ Token ใช้ยืนยันตัว Runner ให้เก็บเป็นความลับ และอย่าวางลงในไฟล์หรือส่งให้ผู้อื่น

⚠️ ปัญหาที่เจอบ่อย: ถ้าใน .gitlab-ci.yml ใช้ tags: หรือ runner มี tag เก่ากว่าเดิม เช่น docker แต่ลงทะเบียนไว้เป็น shell หรือ dev แล้ว pipeline จะไม่เริ่มเลย เพราะ runner ไม่ตรง tag จึงถูกคัดออกโดยอัตโนมัติ
แก้ไขง่าย: ให้ tag ใน .gitlab-ci.yml ตรงกับ tag ที่ลงทะเบียนไว้ เช่น tags: [shell] หรือ tags: [dev] และถ้าจะให้สะดวกกว่า ให้เลือกใช้ Run untagged jobs พร้อม tag ที่ชัดเจนไปเลย

STEP 5.3: ติดตั้งและลงทะเบียน GitLab Runner (Shell Executor) บนเครื่อง VM1 (.31)

การใช้ Shell Executor บน VM1 เป็นวิธีที่เสถียรและเร็วที่สุดในการแข่งขัน เพราะเรียกใช้คำสั่ง docker และ ssh ของเครื่อง VM1 ได้โดยตรง ไม่ติดปัญหา Docker-in-Docker พังหน้างานครับ

[VM1] 1. เพิ่มแหล่งแพ็กเกจ ติดตั้ง gitlab-runner และให้สิทธิ์รัน Docker 
sudo apt update
sudo apt install -y curl ca-certificates
curl -L "https://packages.gitlab.com/install/repositories/runner/gitlab-runner/script.deb.sh" | sudo bash
sudo apt install -y gitlab-runner
sudo usermod -aG docker gitlab-runner
sudo systemctl restart docker
sudo systemctl restart gitlab-runner
sudo systemctl enable --now gitlab-runner

คำสั่ง apt install gitlab-runner เปิดบริการไว้ก่อนเข้ากลุ่ม docker ดังนั้นต้อง restart gitlab-runner ด้วย ไม่งั้นขั้น build จะขึ้น permission denied ที่ /var/run/docker.sock

[VM1] 2. เพิ่มชื่อโดเมนลง /etc/hosts ของ VM1 เพื่อให้ Runner รู้จัก gitlab.mydomain.lab ทันที 
echo "192.168.10.32 gitlab.mydomain.lab app.mydomain.lab" | sudo tee -a /etc/hosts
[VM1] 3. ลงทะเบียน Runner ด้วย Runner authentication token จากหน้าเว็บ 
sudo gitlab-runner register \
  --non-interactive \
  --url "http://gitlab.mydomain.lab" \
  --token "วาง_Runner_authentication_token_glrt-..._ตรงนี้" \
  --executor "shell" \
  --description "vm1-shell-runner"

ถ้าต้องการกรอกทีละ prompt แทนคำสั่งด้านบน: บน VM1 รัน sudo gitlab-runner register แล้วตอบตามที่หน้าจอถาม (ข้อความ prompt อาจต่างกันเล็กน้อยตามเวอร์ชัน):

  1. GitLab instance URL: http://gitlab.mydomain.lab (ต้องเป็น http ตามคู่มือนี้)
  2. Token: วาง Runner authentication token ที่คัดลอกจากหน้าเว็บทั้งชุด ซึ่งขึ้นต้นด้วย glrt-
  3. ถ้าถาม description ให้ใส่ vm1-shell-runner
  4. ถ้าถาม executor ให้พิมพ์ shell

วิธีกรอกทีละ prompt ช่วยไม่ให้ token อยู่ในคำสั่งที่บันทึกใน shell history จึงเหมาะเมื่อกังวลเรื่องความลับ ส่วนคำสั่ง --non-interactive ด้านบนสะดวกกว่า แต่ token จะอยู่ในบรรทัดคำสั่งที่นำไปรัน

ตรวจสอบหลังลงทะเบียน: บน VM1 รันคำสั่งต่อไปนี้ หากไม่พบ error ให้กลับไปหน้าโปรเจกต์ GitLab ที่ Settings → CI/CD → Runners และตรวจว่ามี Runner ที่สร้างไว้

sudo gitlab-runner verify
sudo systemctl status gitlab-runner --no-pager

ถ้า Runner ไม่แสดงหรือไม่ทำงาน ให้ตรวจว่า VM1 resolve gitlab.mydomain.lab ได้ และ URL/Token ถูกต้องก่อนเริ่มลงทะเบียนใหม่

STEP 5.4: สร้าง SSH Key ให้ gitlab-runner บน VM1 ข้ามไปสั่งงาน VM2 (.32) โดยไม่ถามรหัสผ่าน

ขั้นตอนนี้สำคัญมาก! เพราะตอนรัน Stage deploy ตัว GitLab Runner (ซึ่งทำงานภายใต้ชื่อผู้ใช้ gitlab-runner บน VM1) จะต้อง SSH ข้ามไปที่ user1@192.168.10.32 พอร์ต 2222 เพื่อสั่งดึง Image และรันเว็บแอป

[VM1] 1. สลับเข้าตัวผู้ใช้ gitlab-runner แล้วสร้าง SSH Key และส่งไปที่ VM2 
sudo su - gitlab-runner
ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519
ssh-copy-id -p 2222 user1@192.168.10.32
⚠️ ถ้า SSH Login ครั้งแรกไม่ผ่าน หรือเคย login กับ VM2 แล้ว key เปลี่ยน/ล้าสมัย ให้ล้าง cache host key ก่อน: ssh-keygen -R "[192.168.10.32]:2222" (รันในตัวผู้ใช้ gitlab-runner เพราะ SSH พอร์ต 2222 จะเก็บ key ไว้ในชื่อ [IP]:2222) แล้วลอง login ใหม่อีกครั้ง

* ตอนรัน ssh-copy-id ระบบจะถาม Are you sure you want to continue connecting (yes/no)? ให้พิมพ์ yes แล้วกรอกรหัสผ่านของ user1 บนเครื่อง VM2

[VM1] 2. ทดสอบยิงคำสั่งข้ามไปเช็ก Docker บน VM2 และออกจาก gitlab-runner 
ssh -p 2222 user1@192.168.10.32 "sudo docker ps"
rm -f ~/.bash_logout
exit
✅ เคล็ดลับสำคัญ: คำสั่ง rm -f ~/.bash_logout บน user gitlab-runner ช่วยป้องกันบั๊กของ Ubuntu ที่ชอบทำให้ GitLab Runner ค้างตอนเตรียมสภาพแวดล้อม (Prepare environment failed) ครับ!

// 1. Mock Data จำลอง
let tasks = [
  { id: 1, title: "ติดตั้งระบบ GitLab บน VM1", dept: "เครือข่าย", status: "เสร็จสิ้น" },
  { id: 2, title: "คอนฟิก Technitium DNS", dept: "เครือข่าย", status: "รอดำเนินการ" },
  { id: 3, title: "ออกแบบ UI Frontend ด้วย Vanilla JS", dept: "พัฒนาเว็บ", status: "เสร็จสิ้น" }
];

// 2. ฟังก์ชันแสดงตาราง + กรองค้นหา (Search)
function renderTable() {
  const keyword = document.getElementById("search").value.toLowerCase();
  const tbody = document.getElementById("task-list");
  tbody.innerHTML = "";

  const filtered = tasks.filter(t => 
    t.title.toLowerCase().includes(keyword) || 
    t.dept.toLowerCase().includes(keyword)
  );

  if (filtered.length === 0) {
    tbody.innerHTML = `<tr><td colspan="5" align="center" style="color: #94a3b8;">ไม่พบข้อมูล</td></tr>`;
    return;
  }

  filtered.forEach(t => {
    const isDone = t.status === "เสร็จสิ้น";
    tbody.innerHTML += `
      <tr>
        <td>#${t.id}</td>
        <td class="${isDone ? 'status-done' : ''}">${t.title}</td>
        <td>${t.dept}</td>
        <td class="${isDone ? 'status-done' : 'status-pending'}">${t.status}</td>
        <td>
          <button class="btn-toggle" onclick="toggleStatus(${t.id})">${isDone ? 'แก้เป็นรอ' : 'ทำเสร็จ'}</button>
          <button class="btn-del" onclick="deleteTask(${t.id})">ลบ</button>
        </td>
      </tr>
    `;
  });
}

// 3. เพิ่มข้อมูลใหม่ (Add)
function addTask(e) {
  e.preventDefault();
  const titleInput = document.getElementById("task-title");
  tasks.unshift({
    id: tasks.length > 0 ? Math.max(...tasks.map(t => t.id)) + 1 : 1,
    title: titleInput.value,
    dept: document.getElementById("task-dept").value,
    status: "รอดำเนินการ"
  });
  titleInput.value = "";
  renderTable();
}

// 4. สลับสถานะ (Toggle Update)
function toggleStatus(id) {
  const item = tasks.find(t => t.id === id);
  if (item) {
    item.status = item.status === "เสร็จสิ้น" ? "รอดำเนินการ" : "เสร็จสิ้น";
    renderTable();
  }
}

// 5. ลบข้อมูล (Delete พร้อม Confirm Dialog)
function deleteTask(id) {
  if (confirm(`ยืนยันการลบรายการ #${id}?`)) {
    tasks = tasks.filter(t => t.id !== id);
    renderTable();
  }
}

// เรียกแสดงผลทันทีเมื่อเปิดไฟล์
renderTable();

export function useMenu(roleInput = 'user') {
  const r = isRef(roleInput) ? roleInput : ref(roleInput)
  const config = useRuntimeConfig()

  const menu = computed(() => {
    const key = normalizeRole(r.value)
    const base = String(config.public.apiBase || 'http://api.mydomain.lab').replace(/\/$/, '')
    const sections = MAP[key] || MAP.user
    return sections.map((sec) => ({
      ...sec,
      items: sec.items.map((it) =>
        it.label === 'API Docs' ? { ...it, href: `${base}/docs` } : it
      ),
    }))
  })

  return { menu }
}
